# EDF Witness Performance

This note records local implementation measurements for schema-version 3
jittered periodic EDF witnesses. The measured artifact is a CBOR witness file
generated by the untrusted Rust tool and checked by the extracted Haskell
checker.

These measurements characterize executable artifacts, not the abstract EDF
witness interface. The common layer remains the schema-v3 compact DBF
certificate obligation over proof-facing natural-number semantics. The
checker-local `N` kernels, CBOR encoding, and Rust generator caps are
implementation choices behind stable extracted checker entry points.

## Observations

- The Rust generator can emit the `cap_stress` witness below the 10M cap. With
  `--threads auto`, generation took 1.77 seconds and peaked at 124,032 KiB.
- The `cap_stress` CBOR witness is 30,556,592 bytes, about 29.1 MiB.
- The extracted Haskell checker accepted the same `cap_stress` witness, but it
  is the dominant cost: 875.53 seconds and 1,297,152 KiB peak RSS.
- The cap is not an early memory guard in the Rust implementation. The compact
  basis is constructed and counted before the generator rejects a count above
  the configured cap.
- The small cases round to `0.00` seconds under the recorded time format; they
  are useful as smoke cases, not as precise microbenchmarks.

## Refinement And Trust Boundary

Rust witness generation remains untrusted. The trusted path is the Rocq-verified
checker obligation: the checker validates the compact basis required by the
certificate and checks the DBF condition against the proof-facing semantics.
Rust-side caps, benchmark timing, serialized size, and local resource behavior
are operational facts only; they do not weaken or extend the common proof
obligation.

The cap belongs to the concrete tooling layer. A cap failure means the Rust
generator refused to emit a witness under a local resource policy; it does not
mean that the task set is unschedulable. The cap is intentionally absent from
the CBOR certificate fields and from the Rocq common interface.

There is no concrete Awkernel runtime impact. This measurement and the cap
option add no scheduler hooks, interrupt paths, timer behavior, queue state,
trace rows, adapter-visible scheduling policy, or runtime event surface.
